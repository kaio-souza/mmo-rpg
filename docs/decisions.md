# Decisions

The decisions in force. When one changes, edit its row and add the date; a reversed decision keeps a line saying what replaced it.

| # | Decision | Why |
|---|---|---|
| D1 | **The product is a kit** for 2D isometric MMOs with an editor, MIT licensed. Riftara is an example in `examples/riftara/`, not part of the kit. A new game starts from `templates/new-game/`. (2026-11-20) | The engine was already generic; the value is in letting others make their games |
| D2 | **Documentation in English**, like code and content. (2026-11-20; before, docs were in Portuguese) | One language for everything a contributor reads |
| D3 | **Rust only**; nothing to install but `rustup` and the default C compiler; no system libraries | Builds anywhere, clean containers included |
| D4 | **Authoritative server, tile-based movement**, one creature per tile | Cheating is impossible by construction; simple to sync and lag tolerant |
| D5 | **Content is RON data with no scripting**: closed blocks (conditions, effects, objectives, rewards, bonuses) | Designers change the game without code; content cannot crash or exploit the server |
| D6 | **Content only grows**: ids are forever, requirements count for earning, new variants are appended | Updates never take anything from players |
| D7 | **A new content type is done only with its editor form and validation** | The editor is how games are made |
| D8 | **Art and sound are called by name**; missing art falls back to a generic shape | Swapping the look is swapping files |
| D9 | **Isometric 64×32 tiles, 64×64 character frames, 4 drawn directions in strips** (south, west, north, east) | One format for tools, art and renderer |
| D10 | **20 ticks per second**; overload slows time and degrades by levels, never skips ticks | Fast enough for tiles, predictable under load |
| D11 | **One server binary, modes `all`, `gateway`, `zone`**; zones share no state | Scaling out is configuration |
| D12 | **Open world of hidden zones joined by seams** (24-tile ghost band, hand-over past the border) | One map for players, fixed partitions for the server |
| D13 | **Deterministic simulation** with replays and state hashes; `hecs` ECS in `sim` | Bugs can be replayed; crashes are isolated per zone |
| D14 | **Items have identity and no `Clone`**; one owner per item, atomic saves for trades and escrow | Duplication is impossible |
| D15 | **TCP + TLS (`rustls`)**, `postcard` frames, transport swappable; browser clients use a **WebSocket** (`wss://`) on a second port carrying the same frame stream. (2026-11-25: WebSocket added) | Secure now; the browser transport came without touching messages ([web](web.md)) |
| D16 | **Every text is a translation**: keys only, languages as data (`locales.ron`), English first, the AI agent translates the rest in the same change; content texts resolved by the client from a cached text pack | Ten languages from day one at no runtime cost |
| D17 | **SQLite** with versioned character sheets and migrations; Postgres behind the same interface later | Zero setup for small servers |
| D18 | **Client on `wgpu` and `winit`**, own audio mixer with per-platform backends | Linux, Windows and the browser from one code base, no system libraries |
| D19 | **2000 players per world** (ceiling 3000), more worlds beyond that; every tick under Astonia's 41.7 ms | Matches what other MMOs do; measured on one zone ([performance](performance.md)) |
| D20 | **Login defence**: attempts count on arrival per IP, account+IP and account; growing waits stored in the database; device tokens; proof of work under attack; 8 connections per IP | Brute force and account locking without hurting real players ([security](security.md)) |
| D21 | ~~**Interface texts are built into the client**~~ Replaced by D26. | — |
| D23 | **The editor is how a designer runs a published game**: reachable only on the server's private network (VPN), never on the public internet; login with game accounts and roles, draft → publish with hot reload, history with restore; no terminal or files. (2026-11-20) | The people who make the game do not program |
| D24 | **The private network is WireGuard, self-hosted and set up by the kit** (not a managed VPN such as Tailscale). Installed from the system's package manager, never bundled, so its GPLv2 does not touch the kit's licence; free, no user limit. (2026-11-20) | No third party, no cost, no limit; selling the kit or a game stays free of the GPL ([operations](operations.md#private-network-planned)) |
| D25 | **Failures are domain errors, never panics**: `unwrap` and `expect` denied workspace-wide (allowed in tests); the tick crates (`sim`, `combat`, `progression`) also deny unchecked arithmetic and use saturating or checked operations. (2026-11-20) | Validation already refuses broken content; a panic mid-tick would undo that and drop a zone's players. Saturating gives the same results as plain arithmetic, so replays and state hashes do not change ([security](security.md)) |
| D22 | **Kit and example in one repository** | Tests run on the example's data; no versioned API to publish yet |
| D26 | **The client reads its interface texts from the game folder when it starts** (`--content` and `--assets`, default `content` and `assets`); the English title (`ui.game.title`, lower case) is the game id for the user, cache and audio folders, so a package or a moved folder keeps the player's settings. One client binary serves any game; a new game needs no Rust build. (2026-11-20) | Replaces D21. The built-in fallback theme still comes from the template until the kit defaults are one package ([roadmap](roadmap.md)) |
| D27 | **One command for a game: `mmo`** (`new`, `edit`, `check`, `play`, `publish`). It runs the kit's `server`, `client`, `editor` and `validate` from the folder beside it, and depends on no crate. `publish` writes a local package folder, not an upload; uploading comes with the release workflow ([roadmap](roadmap.md)). (2026-11-20) | A new game is one command away and runs with one more |
| D28 | **Characters are layers tinted by content colours**: a body sprite in the skin colour, the body's clothes as drawn, a hair sprite in the hair colour; tinted art is light grey. The world, the creation preview and the character list draw the same layers, and creation offers only the lists that change them. (2026-11-20) | One body and a few hair styles give every combination of skin and hair colour without new art; the preview never promises a look the game does not draw |
| D29 | **One client code base also builds for the browser** (`wasm32`): platform differences live in `client-net` (WebSocket), `client-files` (a bundle fetched at start and `localStorage`), `client-audio` (WebAudio) and the renderer (WebGPU, else WebGL2); the game's files go as one `game.bundle` made by `web-bundle`. (2026-11-25) | Players try a game from a link with nothing to install; the desktop client stays the same program ([web](web.md)) |
| D30 | **The editor's Play and New game buttons run `mmo`**, the binary beside it, instead of linking the tools: the editor keeps its crate edges. A new game goes beside the open game's folder and gets its own editor on a free port, opened in a new tab. (2026-11-26) | A designer starts and tries a game without a terminal |
| D31 | **Character layers are content, not engine rules**: look parts and equipped items are all layers the designer defines in the editor (id, drawing order, sprites); an item names its layer. The template starts with body, hair, top and legs. (2026-11-26) | Drawing one layer over another works the same for any item, so nothing is fixed in code and a game segments its overlays as it wants ([character parts](character-parts.md#5-layers-are-content-equipment-included)) |
| D32 | **A lost siege always costs**: defender loses the town, 30% of the armoury (named items keep their makers) and 20% of the treasury, and its works are damaged; attacker loses its stake and siege works. Shares are content. (2026-11-27) | Sieges must matter on both sides; items carry their history ([kingdoms](kingdoms-and-nations.md#losing-a-siege)) |
| D33 | **Fines are never forced and never ban**: an unpaid fine lowers the player's standing in that town only, with bands (prices, no trade, hostile guards, no services); appeal to the king or moderators. (2026-11-27) | Consequences through the world, not through account punishment |
| D34 | **Instances are budgeted in units** (dungeon 1, raid 8), 20 per thread, 4 threads per process, world cap 160, all in server configuration; numbers to be confirmed by the W9 benchmark. (2026-11-27) | An estimate from measured costs, safe under the 41.7 ms tick ([dungeons](dungeons-and-raids.md#how-many-instances-estimate-to-be-measured-in-w9)) |
| D35 | **AI writes only in the editor**, translated into every active language before publish; nothing is generated at runtime. (2026-11-27) | Deterministic game; every line players read was reviewed ([living NPCs](living-npcs.md#ai-in-the-editor)) |
| D36 | **Armoury gear is lent only during a siege defence**: ownership never moves, the loan lives only in the siege regions and window, and returns on leaving, logout, death or the window's end; the gateway returns every loan when a siege ends. (2026-11-27) | Defenders use the town's named gear without any way to keep or stretch it ([projects](server-projects.md#lending-armoury-gear-in-a-defence)) |
| D37 | **A dungeon finder** forms parties by role and level; dungeons may scale for small parties and fill roles with NPC mercenaries. (2026-11-27) | Many players play alone ([dungeons](dungeons-and-raids.md#finder)) |
| D38 | **Key NPCs may die and leave heirs** defined in content, who inherit role and part of the memory. (2026-11-27) | The world changes and still remembers ([living NPCs](living-npcs.md#heirs)) |
| D39 | **Town taxes per group** (holder, allied, citizen, foreign) set by the lord within limits from the editor. (2026-11-27) | The designer controls favouritism; legitimacy prices it ([kingdoms](kingdoms-and-nations.md#taxes-by-membership)) |
| D40 | **One town per guild**; kingdoms grow through vassal guilds. (2026-11-27) | No monopoly; more guilds rule something ([kingdoms](kingdoms-and-nations.md#one-town-per-guild)) |
| D41 | **The dungeon finder stays inside one world.** (2026-11-27) | Characters and items belong to one world's database; quiet worlds get solo scaling, mercenaries and world merges ([dungeons](dungeons-and-raids.md#finder)) |
| D42 | **The chronicle keeps every NPC succession; inherited memory stays bounded** (from the predecessor only, compounding shares, capacity). (2026-11-27) | Content only grows, but memory per NPC must stay small ([living NPCs](living-npcs.md#heirs)) |
| D43 | **No alliance or kingdom holds more than 25% of claimable towns** (editor setting); alliances up to 5 guilds. (2026-11-27) | One town per guild is not enough if guilds band together ([kingdoms](kingdoms-and-nations.md#one-town-per-guild)) |
| D44 | **Character colours come only from the game's palettes**, never a free picker. (2026-11-27) | Art is called by palette keys ([D8](decisions.md)); the designer keeps the look coherent |
| D45 | **New art and sound reach clients by content hash**: checked on login like the text pack, and fetched in the background when a publish happens while online; missing art falls back to the generic shape until it arrives. (2026-11-27) | Same path as texts ([D16](decisions.md)), no client release, nothing breaks while downloading |
| D46 | **Live content lives outside the release** (`/var/lib/<game>/content`); the editor is its only writer on the server; a developer syncs through the editor's versions (export / import a version), never by copying files. (2026-11-27) | Releases can be replaced without touching content; history and restore stay the single record (E3, E4) |
| D47 | **Browser audio moves to an `AudioWorklet`**, the script node only as fallback. (2026-11-27) | The script node is deprecated and runs on the main thread |
| D48 | **Tile size, frame size, directions and tick stay fixed** ([D9](decisions.md), [D10](decisions.md)); the **number of bodies** becomes content. (2026-11-27) | Every tool, art file and benchmark depends on the fixed ones; bodies are purely data |
| D49 | **The template ships a small set of CC0 interface sounds** through the kit defaults package (roadmap 7), with credits; generated sounds go through `testes-arte/` first. (2026-11-27) | A new game should not be silent; licences stay clean |
| D50 | **SQLite stays**; Postgres comes behind the same interface only when a world's measured save latency exceeds its budget. (2026-11-27) | [D17](decisions.md) holds; no second database without a measured need |
| D51 | **Across seams**: combat reaches through the ghost band and is resolved by the target's zone one tick later; groups work across zones through the gateway; trades and loans need both players in the same zone; no gate queue. (2026-11-27) | Keeps atomic item moves simple ([D14](decisions.md)) and the seam invisible for fighting |
| D52 | **An overloaded zone queues entries** (position and estimate, like the login queue) instead of refusing them. (2026-11-27) | "A queue instead of a wall" is already the kit's promise |
| D53 | **TOTP second factor**: optional for players, **required for editor roles** (admin, designer, moderator). (2026-11-27) | The editor can change the live game ([D23](decisions.md)) |
| D54 | **Bot telemetry for routes and reaction time runs in the gateway on sampled data**, never in the tick, and only flags for a person to review. (2026-11-27) | No tick cost; no automatic bans |
| D55 | **World quests**: offered by their NPC and optionally on a town board; a `Kill` counts for every group member in sight; signal windows are written in seconds and run in ticks. (2026-11-27) | Group play is rewarded; determinism kept ([world quests](world-quests.md)) |
| D56 | **Towns**: the tax replaces part of the shop sink (prices unchanged); one home town per character (fee and cooldown to change); tax reports applied once per zone and window; one vote per account per town. (2026-11-27) | Money circulates without raising prices; no double counting; no alt votes ([towns](towns-and-politics.md)) |
| D57 | **Crafting**: a production class widens minigame windows by tier and adds to the bonus; big pieces may be crafted by up to 4 players, all signed. (2026-11-27) | Specialists feel special; collective works feel collective ([crafting](crafting-minigames.md)) |
| D58 | **Guilds**: names unique per world (normalised); wars cannot be refused by default, but young guilds are protected (editor setting). (2026-11-27) | No impersonation; war has teeth without preying on newcomers ([guilds](guilds.md)) |
| D59 | **Mounts and companions**: the first version dismounts on combat; companions cross seams with their owner. (2026-11-27) | Smaller first step; one hand-over path ([mounts](mounts-and-companions.md)) |
| D60 | **Unique titles and classes pass to an heir** when the holder has not played for the content's `heir_after_days` (0: never); the holder loses it on the next visit, a unique class falls back to the class it specialized. The gateway decides who holds what (`unique_holders`), since zones cannot see each other; two zones granting it in the same instant are settled by the database, and the later one is taken back at once. (2026-11-27) | Legendary classes and relics are the heart of many [genre references](genre-references.md); an opt-in exception to [D6](decisions.md) chosen by the designer, never a content update taking things away |
| D61 | **Server firsts and rankings live in the gateway**: firsts are written once (`server_firsts`); rankings are built from the saved sheets at most every 5 minutes and answered in the chat (`/ranking`, `/firsts`), no window yet. (2026-11-27) | The gateway is the only place that sees every zone; the tick stays free of database work |
| D62 | **Statuses and boss phases are closed blocks** on techniques and monsters (`Poison`, `Stun`, `Slow`; phases by HP share), not the planned `boss_phases/` scripts; drawn ground warnings, summons and enrage wait for instances (W9). (2026-11-27) | A first step the editor already edits, deterministic and fixed point |
| D63 | **Player homes are persistent instances keyed by owner**; crops and eggs advance by the world day computed when the home loads, never by a timer; neglect loses a bonus, never the harvest. (2026-11-27) | No map space, no cost while empty, deterministic; players return for rewards, not fear ([homes](player-homes.md)) |
| D63 | **Instance copies run in the gateway's process** (mode `all` or `gateway`), on the zone clock, linked in memory, with runtime zone ids only the gateway knows; a party is its leader at the moment of entry; a character is never saved inside a copy, only at its exit. Copies in separate zone processes come with the W9 benchmark. (2026-11-27) | The smallest step that runs real dungeons; nothing about a copy survives a restart, so nothing can be lost in one |
| D64 | **A dungeon lockout bars entry** until the next reset (UTC midnight or Monday), instead of the planned "loot once per period"; lockouts live in the gateway (memory and `lockouts`), clears are kept per party (`dungeon_clears`) for the fastest-clear rankings. The door checks level and group size in the zone, before the player leaves it. (2026-11-27) | Simple to explain and to enforce in one place; loot rules come with raids |
| D65 | **A unique item exists once**: the zone that makes it claims it through the gateway (`unique_holders`, key `item:<id>`, no heir); every zone knows which exist and never drops or crafts them; breaking or selling frees it. Two zones making it in the same instant are settled by the database and the later piece is taken back. (2026-11-27) | Relics with one owner are the heart of several [genre references](genre-references.md); trading keeps the piece, so the record is "it exists", not "who holds it" |
| D66 | **A rare class is an ordinary class that requires a title** (`ClassReq::Title`), not a hidden flag: classes are only offered once their requirements hold, so a title earned by a deed is both the secret and the door. (2026-11-27) | One appended requirement variant reuses titles (counters, proficiencies, deeds, uniqueness) instead of a second unlock system |
